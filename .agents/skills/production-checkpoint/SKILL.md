# 制作检查点

第二作返工的主要原因不是缺少经验，而是做决定的那一刻没有用上已有经验（见[第二作复盘](../../../works/0002-zaporozhian-reply/delivery/retrospective-2026-10-29.md)）。本 Skill 只负责在那一刻把人带到正确位置并留下结论。检查问题和案例维护在[制作经验入口](../../../docs/production-lessons.md)和作品复盘里；第 3 节只用一句话提示最常漏掉的动作，具体做法以入口为准，两处冲突时以入口为准。

## 1. 判断时机

| 正在做什么 | 时机（制作经验入口表格中的行） |
| --- | --- |
| 新会话续接某部作品的制作 | 续接作品 |
| 设计段落、改故事事件；牺牲、救援、逃离、群戏、回画 | 确定故事与难场面 |
| 写完或改了生成正文；裁图、选参考；准备上传、核价或申请授权 | 本地冻结输入、随后按授权准备执行 |
| 生成或下载完成，要用末帧、末态或动作接下一段 | 生成完成、启动后继前 |
| 片段接入工作片；收到成片反馈；创作者再次指出同类问题 | 接入工作片、反馈重复时 |
| 字幕、信件、片尾资料、增强、标题描述、发布 | 完整候选与发布准备 |

同时命中几个时机，就各读对应行，合并成一次结论。是否“同类问题”看症状，不看措辞：先查本作品问题表（作品目录下的 `production/problem-ledger.csv`）的问题ID；表里没有，就对照最近几轮反馈。问题第一次出现、可能反复时就登记一行，第二次才有据可查。

简单镜头只做该时机里与它相关的一两项（例如换一张参考图，上传前的离线文件检查仍要做），不另开研究或方案比较；付费生成和核价前的授权照常，见末尾“边界”。调用后发现并不涉及制作决定，写一句“检查点：不适用”和原因即可。

## 2. 只读需要的部分

1. 在制作经验入口读该时机那一行：三个问题和“最小留下什么”。
2. 该行列出的案例按问题选读一两个，先读“最小依据”：当时的输入、出错表现、怎么改的。对照现在的材料判断是否同类；不同类就写明哪个条件不一样，不硬套。
3. 同类反馈再次出现，另读入口的“同一问题反复时怎样收敛”。生成完成或要写“通过”时，另读“每轮只记录一个短结论”下面关于证据和关键依赖的两段。
4. 续接和付费准备另读[当前执行平台](../../../docs/execution-platform.md)。本机装了什么技能、历史文件名、旧授权都不是执行依据。

不通读 `docs/history/` 或整篇复盘。

## 3. 命中时必须做到的动作

三个问题都要落到具体对象：哪份正文、哪张图、哪个时码、哪句反馈。下面几处是第二作反复漏掉的：

- **冻结正文**：先不看解释，像普通读者一样复读最终正文，说出谁对谁做什么；再按字面模拟全部约束，问“演员完全照做，主行动还会发生吗”。剪辑理由不进模型输入。
- **上传素材前**：对最终文件做执行平台列出的离线检查。那些条件只对记录的平台、模式和日期成立；模式不同就写明“未核实”，不断言一定被拒或一定可用。
- **同类反馈再次出现**：写出原假设、新证据、这次改什么、预计看到什么；写不出来就停止付费重试，改为提出实质不同的处理请创作者选。
- **生成完成后**：先确认主行动、受力来源和人物反应是否成立，再用末态启动下一段。抽帧可以核末态姿势，不能验速度和表演；没法正常速度观看，就暂停依赖它的下一段，请创作者看指定时码。
- **发布前**：按真实时间轴核对标题和描述的承诺；史实、传说、虚构分开写。

每个案例都写有不适用边界，例如 L03 允许必要的沉默和静态原画尾声，L04 不要求每个镜头都运镜。结论不越过这些边界。

## 4. 留下结论

- 回复创作者时，在行动前写一行：`检查点：<时机>｜相关：<案例ID或“无”>｜结论：<一句话>`，让创作者能看到这次检查有没有发生。
- 每轮在作品制作卡按制作经验入口“每轮只记录一个短结论”的格式记一次，不是每次调用都记。反复出现的问题在问题表对应行更新根因假设和下次付费的新证据。不另建文件。
- 结论涉及主题、人物动机、结局、故事事件或段落结构的改变，或新的付费、上传、核价等外部操作时，停下来合并成一次提问；其余由 Codex 直接完成。

## 5. 出现新经验时

按制作经验入口的“新经验”格式写进作品复盘，附最小依据（原词或原话、出错表现、修改结果）。只有新增条件、反例或执行方法才改入口表，并链接到新案例。改了本 Skill 的触发措辞或时机路由，或改了案例结论，按[评测](evals.md)比较改前改后；运行评测会消耗模型额度，先征得创作者同意。

## 边界

本 Skill 不产生授权，也不替代创作者观看与定稿。每次付费生成都需要创作者明确授权和积分上限；云端保存、读回和核价需要先有覆盖它们的准备授权，见 [AGENTS.md](../../../AGENTS.md) 和制作经验入口。
