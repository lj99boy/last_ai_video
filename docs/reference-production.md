# 参考驱动的制作：资产、段落组合与执行

2026-10-17。本文把[整体流程](workflow.md)与[画作到故事方法](painting-to-story-playbook.md)落实为可审查的资源和执行方式。适用于角色、环境、道具、风格与动作需要跨镜复用的作品；简单镜头可缩减资料，不以资产数量或表格完整度取代创作。它是针对已观察输入冲突的流程改进，尚不宣称已由新生成证明节省比例或稳定性。

## 1. 先设计观众怎样看，再决定提供什么

先用行动—回应—变化组织完整声画：人物要影响谁，观众先看见什么，声音补充什么，此处为什么切镜或移动摄影机。再核人物和物件的位置、进出、接触、归属、行动通道及下一段需要的状态；需要时用简图、线稿或低成本白模排演。不先为所有叙事节拍生成一张完整精细画面，再要求模型逐张动起来。

节拍编号、剪切、精细关键帧和生成调用是不同单位。一段连续行动可以容纳几个节拍，一段生成也可留下多个可剪区间。摄影机在哪一侧、多高、怎样移动，以及允许哪些遮挡，都由观看任务决定；换侧或留在同侧都要让相邻镜头接得清楚，不设全段同侧、全员正面、全身不遮挡或每镜停稳等通用限制。

## 2. 资产按职责复用，认可按属性记录

先审已有图、视频与声音，再决定缺口。素材清单至少能追溯ID、实际路径或可读资源、来源／模型、版本、认可范围和用途；实际取用还需记录指向哪个节点或固定版本的资源。人物资料只定义外貌时，不应同时决定每镜构图；图像含有的无关信息仍可能影响模型。

| 职责 | 选什么资料 | 什么时候补、什么时候不用 |
| --- | --- | --- |
| 人物／年龄／衣装 | 可辨面貌、身形、发型、帽子与当前年代衣装；必要的其他视角 | 不同年龄按时期分开选择，并保留可辨认的面部和身形特征，不把各年龄混成一个默认角色。单图足够则不补三视图；背面表演不为露脸取消。 |
| 环境／空间 | 地貌、通道、材料、光色；必要的人物与道具位置示意 | 风景图不是精确三维场景，也不自动继承旧人物位置。复杂路径才补空间资料，近景不用每次附完整营地／街区。 |
| 道具／结构 | 会影响识别、连续性或受力的部件、破损、握持与落点 | 既有局部够用便复用；不把所有碗、桶、绳都建为独立资产。形制参考不规定观看方向。 |
| 风格／材料 | 所选绘画色面、边缘、冷暖与材料表现 | 挑少含可辨角色或错误年代的资料。避免风格图把它的角色、姿态、情绪、天气和摄影机一起带入。 |
| 动作／运镜／分镜 | 难以由文字表达的路径、遮挡、速度、接触与镜头顺序 | 按未解问题选择线稿、白模或可用音视频，不强制每段参考视频。写清参考中的动作由哪个人物完成；白模中没有设计肢体动作时，不能把它当作完整表演。 |
| 完整人物关系／起止状态 | 复杂交接、承重、多人接触或精确结尾构图需要的状态 | 仅在这些信息必须清楚时制作；简单镜头可由独立人物、环境等资料与文字组织。开始姿态不是全程姿态；普通m2v中的一张图不能未经验证就称严格首帧。 |
| 声音 | 需要的音色、对白内容、节奏或可用原声区间 | 音色、台词与混音分开管理；占位声音不自动成为目标。无此需要不加音频；有声任务必须实际听辨。 |
| 原作来源／精确结尾 | 真实来源档案和明确的最终展示取景 | 仅作品需要精确回画才设计；生成图不能递归取代原作。固定裁切、相框、墙面、溶解与字幕优先本地处理并核实际交接。 |

记录“仅结构可用”“衣装可辨”“画风认可”“完整关系未通过”等范围，避免一个“已认可”覆盖全部属性。需要新资料时，说明它补什么缺口及将替代哪一项；不靠不断叠参考解决冲突。若裁选后仍携带错误姿态或身份，就换更合适资料或重新设计，不能指望用途文字实现硬隔离。

## 3. 能力来源与验证边界

截至2026-10-17，[官方Seedance 2.5指南](https://docs.volcengine.com/docs/ark/seedance-2-5-prompt-guide?lang=zh)列出主体、运动、白模、风格、音频、分镜及关键帧参考；要求明确素材对应关系，也提醒宫格故事板不保证逐格严格还原。指南允许多视图，不应沿用旧版本限制作为2.5硬禁令。官方能力说明不代表每个产品入口和本机接口都已接通。

当日本机公开CLI审计（本地记录 `production/battle-v02/reference-capability-audit.json`）区分了schema、纯本地dry-run与只读模型发现：m2v可组织多种参考，Element可绑定主素材、辅助图片与可选音色。主／辅是组织关系，当前公开合同未暴露人物／环境／风格专用权重；Element不是LoRA，也不是身份锁定。不能将它直接当首尾帧图片槽。上述审计没有真实Element生成结果，不证明构图解耦或成本收益。

以下证据分别记录，不能跳级：**官方文档 → 当前入口schema／本地校验 → 账号与资源可读 → 云端保存读回 → 当前报价 → 实际生成 → 原速创作验收**。使用某能力前复用已有条件相符的证据，条件变化只查受影响部分，不重复全套调研。来源中的数量上限是限制，不是每镜应使用的数量。

2026-10-20按创作者指定来源补充：物料和提示词准备应核对[火山方舟官方指南](https://docs.volcengine.com/docs/ark/seedance-2-5-prompt-guide?lang=zh)，并参考[smixs实践整理](https://github.com/smixs/visual-skills/blob/main/video/references/seedance-25.md)。后者是第三方归纳；它的固定最短时间窗、专用括号、真人毛孔后缀及成本路线不能直接升级为通用规则。具体作品的画风、已确认剧情和消费许可仍按该作品执行。

## 4. 每个实际制作段的组合

用[参考计划模板](../templates/work/preproduction/reference-plan.md)集中记录，同一场面可共享基准，逐段只写差异。复杂作品可用[参考流水线工具](../tools/README-reference-pipeline.md)将资源与组合组织为可检查输入；工具检查不能替代实际审看，也不应自动决定导演方案。

一份可提交组合需要回答：

1. **目标与观看：**对应哪些节拍／成片区间；人物意图、回应、状态变化与注意顺序是什么。
2. **真实关系：**入画人物及当前年龄、相对位置、通道和物件归属；前镜留下什么状态，后镜需要什么。
3. **引用分工：**每个实际图／Element／视频／音频指代谁、提供哪部分、不继承什么；人物与白模、声音之间怎样映射。
4. **模式与动作：**为何用这一模式；主要动作、摄影机和声音怎样变化；源素材时长、数量及可剪条件是什么。
5. **依赖与风险：**是否需要前段实际结束状态，怎样的片段才合格；若前段未通过，不启动哪些后段；有哪些可用素材，失败后怎样替换。
6. **执行边界：**本地来源与云绑定、读回差异、报价及条件、媒体／云写／消费授权、稳定提交身份、实际回执。
7. **验收与回流：**原速看哪些因果、受力、跨龄或群体变化；结果如何改变资产选择、后续组合和问题累计表。

提示词用明确指代组织本镜发生的事，输入精准时少复述无关内容；补足草图未表达的年龄、动作逻辑与声音。优先写主要动作及相关的持续背景事件，不给每个人分配同时启动的动作。写清风吹动什么、谁碰到什么、物件怎样受力；近景可以只保留看得见或听得到的背景变化。

提示词与准备记录分开：模型正文按**有序素材职责 → 一句场景目标 → 镜头顺序或连续动作阶段 → 声音与贯穿约束**组织；参数、消费、选用区间与剪辑余量、指纹和审查条件放制作数据。逐项核实际绑定，不只在图片里写人物姓名；准确参考已有的细节不反复复述。只有关键因果动作需要细写，其他动作概括表达。时间轴可用连续秒级区间或相对事件触发，按任务负荷分配，不套固定最短窗口，也不把提示时点当实际剪点。对白将角色、语气和内容写清，音效／环境／配乐分别处理；使用视频或实际帧时检查烧录字幕等污染，不能只靠一句“无字幕”。这是输入设计依据，不保证生成遵从或直接适用于当前CLI的全部参数。

正文还要逐句读通：写明谁做什么、物体发生什么变化、摄影机从哪里看。不要把内部缩写或自造动词直接送入模型；例如用“两人撑住车梁，车停止向前移动”，不用“把推进咬停”；用“书吏把后面的字写小”，不用“收小笔势”。指代不明的“他／这次反应”和抽象的构图描述也要改清楚。引用、哈希和语义清单检查不能代替这一步。

检查最终完整正文，而非只看改过的词：补齐漏字和动作对象，核对代词指向，采纳的复核建议也须连同上下句重读。单段生成直接说明当前地点和起始状态；“省略旅程”“下一场接战斗”等整片安排留在导演稿。引用前段信息时，确认它确实由本次输入提供；仅有图片参考不能要求模型照搬前段声音方向。需要的情绪、台词语义和摄影要求仍可保留。复核方式和案例见[语言经验](history/practice-notes.md#2026-10-20--提示词与制作说明先让人读懂)。

“同一角色／道具／动作”逐项对应本次实际提供的素材或明确描述。依据不足时保留连续性要求并登记缺口，再决定补文字、复用资料或准备合适参考；不把信息需求当现成文件，也不以补写特征代替实际跨镜核验。取词版本更新后，连同章内入口核对文件路径、正文和对应指纹，历史字段及已执行原件不改。

## 5. 模式按任务选择

| 方式 | 适用理由 | 需要额外警惕 |
| --- | --- | --- |
| m2v多模态参考 | 保持人物身份／环境／风格而重新构图，或结合动作、声音、白模／分镜 | 用途靠明确对应关系与实际效果落实，不是硬权重；多张完整图可能给出互相矛盾的开始状态。时间戳／镜头顺序描述不保证每次精确履行。 |
| 首帧或首尾帧 | 具体的开始或结束画面必须准确匹配 | 检查当前入口的有序图片槽与模式合同；开始与结束状态必须能合理转化，不能一个已完成、一个又倒回开始。首尾符合也不证明中间动作自然。 |
| 本地剪辑／合成／声音组织 | 确定的剪点、时间省略、裁切、溶解、真实原照展示、字幕及已有可用声画 | 真实素材必须足够；不能靠字幕声称未发生的交接，不能用溶解补出从未存在的人群。 |

同一个场面允许混用。Element只在重复引用和资料组织确有价值时使用，直接引用也可；不先批量建全角色Element再考虑镜头。前后段以实际可用片段中的状态衔接，不默认最后一帧恰好合适。明确切镜可以省略无叙事价值的短距离移动，但后镜要让观众看懂人物到了哪里、物件还在谁手中，不用镜像、瞬移或消失伪造连续。

## 6. 执行时核对实际输入与授权增量

先实际审看所有取用资料，再对照**导演原文／整片方案、实际素材与职责、最终提交词、保存后的读回配置**。仅ID存在、文件有哈希或接口通过不能证明图片对；读回参数一致也不能证明动作成立。比较相邻画面时遮去提示词，仍应能说明观察位置为何不同、行动如何接上。

提交前列明这次相对已有许可新增了什么：媒体文件及用途／目的地、Element或节点等云写入、生成次数／模式／时长和最大消费。已授权且条件不变的范围直接沿用，超出部分才确认；重构流程不能恢复已叫停批次、清零尝试或自动扩大消费。新增本地资源不等于授权上传，新云写入许可也不等于付费许可。

实际引用、模式、时长、数量或模型变化，旧报价不再证明新请求的费用；重新保存、读回、核价并核累计上限。执行前保留稳定提交身份；超时或中断按同身份查询真实状态，不自动换身份重跑。实际资源状态或参数与本地组合不一致，先修差异，不以旧成功回执证明新版本可执行。

保存草稿、核价、批准扣费与运行分别记；上传数量、当前报价、预留、逐任务实扣、余额差、人民币和未知值分别记。未实际生成不宣称新路线更省钱；预算上限不是必须花完的目标。

## 7. 用正式段验证，按整段回流

优先清点已付费素材的可用区间，选择能回答关键问题、成功可入片的正式段制作。没有关键未知就不强制样片；不得先买整套测试再自动重拍整套正式版。新角度下仍认得出人物，不代表复杂接触、另一年代、多人共同完成任务与结尾全部通过。

原速带声审完整场面及前后镜头，再放回全片：主要动作是否影响别人或改变处境；背景事件是否适度持续；空间与物件是否接得上；不同年龄的角色是否认得出，人群是否延续；声音是否实际听清；回到原画是否有剧情依据，实际结尾构图是否接得上。抽帧、ASR、解码与响度帮助定位，不能替代观看和听辨。允许静默、反应延迟、固定重物与真实原作静态结尾。

| 问题 | 回到哪里修改 | 什么不能替代修复 |
| --- | --- | --- |
| 人物／时代／风格漂移 | 资产版本、当前年龄、参考组合与实际绑定 | 多加同一错误图、把最近生成图升级为原作基准 |
| 新机位仍像同一张图 | 观看任务、空间设计、完整旧构图的取用职责 | 仅改“更灵动”、数码裁切或镜像 |
| 交接／承重没完成 | 实际开始状态、动作数量与难度、模式、可剪区间及能表达同一剧情的其他方式 | 台词、字幕或笑脸声称动作成功 |
| 主角动而世界凝固 | 背景事件、注意顺序、环境受力和输入约束 | 运动配额、全员循环、烟雾或相机漂移 |
| 接续／时长不合 | 前后镜头剪辑、实际结束状态、源片段与必要省略 | 未核前段就继续购买后段 |

保留可用区间与有价值的意外效果。失败写明原假设、新证据、改变什么、对下一次的预期；按未解问题累计尝试与费用，不换版本清零。无新证据停止该问题的付费循环；有依据的受控重抽仍受原授权与明确上限约束。

## 8. 什么才算完成这一轮

流程、资源清单、段落组合、实际请求与剪辑应互相指向当前版本；旧请求显式历史化，原始素材和回执不覆盖。资源已建、schema通过、云端读回、实际生成和创作通过分别汇报。静态设计结束可以称本地准备完成，不能称新参考法动态验证完成；部分代表段通过也不能代替全片验收。创作者决定最终定稿与发布。
